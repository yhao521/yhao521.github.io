WebLogic面试题回答

发表于2026-05-14|更新于2026-05-18|博客
|浏览量:

WebLogic 作为企业级 Java 应用服务器，在面试中通常围绕基础概念、架构组件、配置管理、集群高可用、性能调优与故障排查这几个核心维度展开。以下结合搜索到的资料，为你梳理了关键面试题的回答要点。

1. 基础概念与架构

问题：什么是 WebLogic 域 (Domain)？它由哪些核心组件组成？
WebLogic 域是一个逻辑上的管理单元，它包含一个管理服务器 (Administration Server) 和若干个受管服务器 (Managed Server) 。

  • 管理服务器：域的中心，存储配置 (config.xml)，提供管理控制台 。
  • 受管服务器：实际运行应用程序的实例 。
  • 节点管理器 (Node Manager)：独立进程，用于远程启停受管服务器，实现故障重启 。

问题：管理服务器挂了会影响应用访问吗？
不会。管理服务器宕机不影响已运行的受管服务器上的业务访问，但此时无法进行配置变更或监控新状态 。

2. 配置与部署

问题：如何给 WebLogic 指定内存大小？
修改域中对应服务器的启动脚本（如 startWebLogic.sh 或 setDomainEnv.sh），设置 JVM 参数 MEM_ARGS。例如：set MEM_ARGS=-Xms1024m -Xmx2048m 。

问题：部署一个 Web 应用，WAR 包应该放在哪里？

  • 常规部署：通过管理控制台安装。
  • 直接放置：可以放在 {DOMAIN_HOME}/servers/{ServerName}/applications 目录下。若需免输入应用名访问，可设置为缺省应用 。
  • 开发模式：放在 autodeploy 目录可实现自动部署 。

问题：修改了连接池或 JMS 后，配置保存在哪个文件？
所有域的配置都保存在该域的 config.xml 文件中 。

3. 集群 (Cluster) 与高可用 (HA)

问题：集群如何实现会话保持（Session 复制）？
集群通过会话复制实现故障转移。当用户请求切换到另一台服务器时，Session 不丢失。需在应用的 weblogic.xml 中配置复制策略（如内存复制） 。

问题：Domain 和 Cluster 的区别是什么？

  • Domain 是行政边界，包含管理和受管服务器，包含配置。
  • Cluster 是可扩展性边界，是 Domain 内一组受管服务器的逻辑组合，用于负载均衡和容错 。

4. 数据源 (JDBC) 与事务

问题：什么是数据源 (DataSource)？JNDI 在这里起什么作用？
数据源是数据库连接池的抽象，应用通过JNDI 名称（如 jdbc/mydb）查找并获取连接，而无需关心物理数据库的具体位置 。

问题：什么是多数据源 (Multi Data Source)？
多数据源是对多个数据源的抽象，用于实现数据库层的负载均衡或故障转移 。

5. 安全 (Security)

问题：如何配置 SSL（单向/双向）？

  • 获取证书（自签名或 CA 签名），配置身份密钥库和信任密钥库。
  • 在控制台启用 SSL 监听端口（默认 7002）。
  • 可选择配置是否需要客户端证书（双向认证） 。

6. 故障排查与性能调优

问题：什么是阻塞线程 (Stuck Thread)？怎么处理？
当请求执行时间超过默认 600秒，该线程即被标记为阻塞 。

  • 常见原因：死锁、慢 SQL、网络延迟。
  • 排查：分析线程转储，检查慢 SQL，优化代码或增加线程池大小。

问题：如何排查内存溢出？

  1. 设置 JVM 参数：-XX:+HeapDumpOnOutOfMemoryError 自动生成堆转储文件 。
  2. 分析：使用 MAT 或 JProfiler 分析 dump 文件。
  3. 检查：重点关注是否未关闭连接、缓存过大或加载数据过多 。

问题：如何设定开发模式与产品发布模式？
可以在管理控制台修改，或修改启动脚本增加 set PRODUCTION_MODE=true 。

7. 自动化与管理

问题：如何实现部署自动化？
可以使用 WLST (WebLogic Scripting Tool)，它是基于 Python 的脚本工具，用于自动化创建域、部署应用和修改配置。也可以集成到 Jenkins 等 CI/CD 工具中 。
