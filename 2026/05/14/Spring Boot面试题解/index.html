Spring Boot面试题解

发表于2026-05-14|更新于2026-05-18|博客
|浏览量:

Spring Boot 的面试通常从基础概念、核心特性，到进阶原理和微服务实战，层层递进。以下整理了一份高频面试题及答案，希望能帮到你：

一、基础概念篇

1. 什么是 Spring Boot？它和 Spring 有什么区别？

  • 回答要点：Spring Boot 是基于 Spring 框架的微服务级框架，它并非替代品，而是对 Spring 的自动配置和简化封装。
  • 核心优势：
    • 简化依赖：通过spring-boot-starter-*启动器，将常用依赖打包，开发者无需再为版本冲突头疼。
    • 自动配置：基于添加的 Jar 依赖，自动配置 Spring 应用，例如添加了spring-boot-starter-web，它会自动配置 Tomcat 和 DispatcherServlet。
    • 嵌入式服务器：直接嵌入 Tomcat、Jetty 等，无需打包成 WAR 部署，通过main方法即可运行。
    • 生产就绪：提供指标（Metrics）、健康检查（Health Check）、外部化配置等监控能力。

2. Spring Boot 的核心注解是什么？

  • 核心注解：@SpringBootApplication，通常放在主启动类上。
  • 它实际上是一个组合注解，包含三个主要部分：
    • @SpringBootConfiguration：本质是@Configuration，表明该类是配置类。
    • @EnableAutoConfiguration：最关键的一步。开启自动配置，让 Spring Boot 根据类路径中的依赖（如 tomcat-embedded.jar）自动创建所需的 Bean。
    • @ComponentScan：启用组件扫描，默认扫描主类所在包及其子包。

二、核心配置与原理篇

3. Spring Boot 自动配置的原理是什么？

  • 核心机制：基于条件注解和spring.factories文件。
  • 源码级回答（加分项）：
    1. 启动入口：@SpringBootApplication 中的 @EnableAutoConfiguration 会导入 AutoConfigurationImportSelector。
    2. 加载 META-INF：AutoConfigurationImportSelector 会扫描所有 Jar 包下的 META-INF/spring.factories 文件。
    3. 读取配置类：读取文件中 org.springframework.boot.autoconfigure.EnableAutoConfiguration 对应的所有配置类全限定名。
    4. 条件过滤：加载这些配置类时，会根据类上的条件注解（如 @ConditionalOnClass、@ConditionalOnBean、@ConditionalOnMissingBean 等）进行判断。只有满足条件（例如 DataSourceAutoConfiguration 需要类路径下有 DataSource.class 且容器中不存在自定义的 DataSource 时），才会执行自动配置。

4. 如何自定义一个 Starter？

  • 命名规范：官方 Starter 命名格式为 spring-boot-starter-xxx，自定义建议为 xxx-spring-boot-starter。
  • 实现步骤：
    1. 创建一个 Maven 项目，引入 spring-boot-autoconfigure 依赖。
    2. 编写业务逻辑服务（XxxService）。
    3. 编写配置属性类（XxxProperties），使用 @ConfigurationProperties(prefix = "xxx") 绑定配置文件参数。
    4. 编写自动配置类（XxxAutoConfiguration），通过条件注解（如 @ConditionalOnProperty）控制是否生效，并在类中创建 XxxService 的 Bean。
    5. 在 resources/META-INF/ 下创建 spring.factories 文件，指定自动配置类：
      org.springframework.boot.autoconfigure.EnableAutoConfiguration=com.example.XxxAutoConfiguration

5. Spring Boot 配置文件 bootstrap.yml 和 application.yml 有什么区别？

  • 加载时机：bootstrap.yml 由父级 Spring 父容器加载，优先于 application.yml 加载。
  • 主要用途：
    • bootstrap.yml：常用于 Spring Cloud 配置中心（Config Server）的连接信息、加密解密密钥等。它通常用于从外部资源加载配置。
    • application.yml：用于应用级别的常规配置，如数据源、端口等。

三、Web开发与数据访问篇

6. Spring Boot 如何解决跨域问题？

  • 全局配置：推荐方式。编写一个配置类实现 WebMvcConfigurer，重写 addCorsMappings 方法。

7. Spring Boot 如何整合 MyBatis？

  • 步骤：
    1. 引入依赖：mybatis-spring-boot-starter 和数据库驱动（如 mysql-connector-java）。
    2. 配置 application.yml：配置数据源（spring.datasource.url、username、password）和 MyBatis 映射文件路径（mybatis.mapper-locations=classpath:mapper/*.xml）。
    3. 编写 Mapper 接口，并在接口上添加 @Mapper 注解，或者在启动类上添加 @MapperScan("com.example.mapper") 批量扫描。

8. Spring Boot 的事务管理是如何实现的？

  • 核心注解：@Transactional。
  • 开启方式：在启动类或配置类上添加 @EnableTransactionManagement 注解（Spring Boot 在 TransactionAutoConfiguration 中已默认开启）。
  • 原理：使用 AOP 实现。当一个方法被调用时，Spring 会检查该方法是否有 @Transactional 注解，如果有，则开启事务，执行 SQL，若出现 RuntimeException 则回滚，否则提交。

四、日志与监控篇

9. Spring Boot 默认使用的日志框架是什么？如何切换？

  • 默认框架：Logback，同时通过 SLF4J 作为日志门面。
  • 切换为 Log4j2：
    1. 排除默认的 spring-boot-starter-logging。
    2. 引入 spring-boot-starter-log4j2。

10. Spring Boot Actuator 有什么作用？

  • 作用：为生产环境提供监控和管理功能，通过 HTTP 或 JMX 端点暴露应用信息。
  • 常用端点：
    • /health：健康状态，常与容器化环境的探针配合使用。
    • /info：获取自定义的应用信息。
    • /metrics：查看内存、GC、请求等指标数据。
    • /loggers：查看和修改日志级别（非常实用）。

12. 如何在 Spring Boot 启动前后执行特定代码？

  • ApplicationRunner 或 CommandLineRunner 接口：
    • 实现这两个接口，并重写 run 方法。
    • 在容器启动成功后，Spring Boot 会回调所有实现了这两个接口的 Bean 的 run 方法。
    • 区别：CommandLineRunner 接收原始字符串参数；ApplicationRunner 接收封装好的 ApplicationArguments 对象，功能更强大。

13. 如何理解 Spring Boot 的 Fat Jar？如何打包和部署？

  • Fat Jar：Spring Boot 的 spring-boot-maven-plugin 会将应用代码、依赖包和嵌入式容器一起打包成一个可执行的 Jar 文件。
  • 打包命令：mvn clean package。
  • 部署方式：java -jar xxx.jar。
  • 常见优化：在启动时通过 --spring.profiles.active=prod 指定环境，或通过 -Xms、-Xmx 设置 JVM 内存参数。

最后，面试中还可以准备一些项目经验，比如如何优化启动速度、如何解决循环依赖，或对 Spring Boot 2.x 和 3.x 差异（如 Java 17+ 和 Jakarta EE 9）的了解，这些都会是很好的加分项。
