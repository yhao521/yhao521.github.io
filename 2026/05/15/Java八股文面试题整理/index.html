Java八股文面试题整理

发表于2026-05-15|更新于2026-05-18|博客
|浏览量:

Java“八股文”面试题通常指的是那些高频出现的、侧重基础原理和底层实现的考题。以下我为你整理了Java核心知识体系中最常见的面试题，按模块分类并附带了精简的要点提示，适合用于快速复习和查漏补缺。

Java八股文面试题整理

一、Java 基础

  1. 面向对象的三大特征？

    • 封装：隐藏内部细节，暴露必要接口，提高安全性。
    • 继承：子类复用父类代码，形成层级关系。
    • 多态：父类引用指向子类对象，运行时动态绑定（编译看左边，运行看右边），提高扩展性。

  2. == 和 equals 的区别？

    • ==：基本类型比值，引用类型比内存地址。
    • equals：未重写时等价于 ==；String、Integer 等类重写了 equals，比较的是内容。

  3. String 为什么是不可变的？

    • String 类被 final 修饰，不可被继承。
    • 底层 char[]（JDK 8）或 byte[]（JDK 9+）被 private final 修饰，且没有提供修改数组的方法。
    • 好处：字符串常量池复用、线程安全、哈希码缓存（作为 HashMap 的键高效）。

  4. StringBuilder 和 StringBuffer 的区别？

    • StringBuffer：线程安全，方法加了 synchronized，性能稍低。
    • StringBuilder：非线程安全，性能高，单线程下推荐使用。

  5. final、finally、finalize 的区别？

    • final：修饰类（不可继承）、方法（不可重写）、变量（不可修改）。
    • finally：异常处理中的代码块，保证一定会执行（除非 JVM 提前退出）。
    • finalize：Object 的方法，GC 回收对象前调用（JDK 9 起已弃用）。

二、集合框架

  1. ArrayList 和 LinkedList 的区别？

    • ArrayList：基于动态数组，随机访问快（O(1)），中间插入/删除慢（需移动元素），扩容机制（1.5 倍）。
    • LinkedList：基于双向链表，随机访问慢（需遍历），头尾插入/删除快。

  2. HashMap 底层原理（JDK 1.8）？

    • 数据结构：数组 + 链表 + 红黑树。
    • 插入流程：计算 hash → 定位索引 → 若为空直接插入，否则判断 key 是否相等 → 遍历链表/树，存在则覆盖，不存在则尾插。
    • 树化条件：链表长度 > 8 且 数组长度 ≥ 64，否则优先扩容。
    • 扩容机制：初始容量 16，负载因子 0.75，扩容为原容量 2 倍，rehash 后元素要么在原位置，要么在原位置 + 旧容量。

  3. ConcurrentHashMap 如何保证线程安全？

    • JDK 1.7：分段锁（Segment 继承 ReentrantLock），将数据分段，每段独立加锁。
    • JDK 1.8：CAS + synchronized，锁粒度更细（仅锁链表/红黑树的头节点），并发度更高。

  4. HashSet 如何保证元素不重复？

    • 底层基于 HashMap，元素作为 HashMap 的 key，value 是一个固定占位对象。利用 HashMap 的 key 唯一性来保证。

三、并发编程

  1. synchronized 的底层实现？

    • 对象头（Mark Word）记录锁状态（无锁、偏向锁、轻量级锁、重量级锁）。
    • 锁升级过程：无锁 → 偏向锁（单线程） → 轻量级锁（CAS 自旋） → 重量级锁（操作系统互斥量，线程阻塞）。
    • 修饰实例方法锁的是当前实例对象，修饰静态方法锁的是 Class 对象。

  2. volatile 的作用？

    • 保证可见性：强制将修改写回主内存，并使其他线程工作内存中的副本失效（通过内存屏障实现）。
    • 禁止指令重排序：在写操作前后插入内存屏障，防止编译器/CPU 乱序。
    • 不保证原子性：count++ 等复合操作仍需加锁。

  3. ThreadLocal 的原理及内存泄漏问题？

    • 每个线程持有 ThreadLocalMap，键为 ThreadLocal 的弱引用，值为存储的变量。
    • 内存泄漏：若 ThreadLocal 对象无外部强引用，GC 时键被回收，导致 Entry 中 value 无法访问。使用后应调用 remove() 方法。

  4. 线程池的核心参数？

    • 执行逻辑：核心线程 → 阻塞队列 → 非核心线程 → 拒绝策略。

四、JVM（Java 虚拟机）

  1. JVM 内存模型（JDK 1.8）？

    • 堆（Heap）：存放对象实例，线程共享，GC 主要区域（年轻代 + 老年代）。
    • 方法区（元空间）：存储类信息、常量、静态变量等。JDK 1.8 起使用本地内存（元空间），替代了之前的永久代。
    • 虚拟机栈：每个方法执行时创建栈帧（局部变量表、操作数栈、动态链接、返回地址）。
    • 本地方法栈：为 native 方法服务。
    • 程序计数器：记录当前线程执行字节码的行号。

  2. 垃圾回收（GC）如何判断对象可回收？

    • 引用计数法（JVM 未采用，存在循环引用问题）。
    • 可达性分析：从 GC Roots（栈引用、静态变量引用、JNI 引用等）出发，不可达的对象即被标记可回收。

  3. 常见的垃圾回收算法？

    • 标记-清除：产生内存碎片。
    • 标记-复制：用于年轻代，分 Eden 和两个 Survivor 区（比例 8:1:1）。
    • 标记-整理：用于老年代，清除碎片。

  4. CMS 和 G1 的区别？

    • CMS（Concurrent Mark Sweep）：以获取最短停顿时间为目标，基于标记-清除，会产生碎片，浮动垃圾，JDK 9 起已弃用。
    • G1（Garbage First）：将堆划分为多个 Region，可预测停顿时间模型，采用标记-复制整体，局部采用标记-复制或标记-整理，无碎片，更适合大堆内存。

五、Java Web 与框架

  1. Spring 的 IOC 和 AOP？

    • IOC（控制反转）：将对象的创建、依赖管理的控制权交给 Spring 容器，通过 DI（依赖注入）实现，降低耦合。
    • AOP（面向切面编程）：通过动态代理（JDK 动态代理或 CGLIB）将日志、事务等横切逻辑与业务逻辑分离。

  2. Spring 中 Bean 的生命周期？

    • 实例化 → 属性注入（populate） → 执行 Aware 接口方法 → 执行 BeanPostProcessor 前置处理 → 执行 @PostConstruct / init-method → 执行 BeanPostProcessor 后置处理 → 注册销毁回调 → 销毁（@PreDestroy / destroy-method）。

  3. MySQL 的索引结构为什么用 B+ 树？

    • B+ 树相比 B 树：非叶子节点只存键值，可存储更多索引，降低树高；叶子节点形成有序链表，范围查询性能高。

  4. Redis 为什么这么快？

    • 基于内存操作；单线程模型（避免上下文切换和锁竞争）；I/O 多路复用（非阻塞 I/O）；高效的数据结构（如 SDS、跳表）。

六、复习建议

  • 理解优于背诵：面试官通常会根据你的回答深入追问源码或场景题，机械背诵容易露怯。
  • 动手实践：针对 HashMap、ConcurrentHashMap、线程池等，自己写代码验证并发场景下的表现。
  • 画图记忆：JVM 内存模型、锁升级过程、GC 流程等，用图示辅助记忆会更牢固。
  • 关注 JDK 版本演进：如 JDK 8 到 JDK 17/21 的变化（如虚拟线程、ZGC 等），体现技术视野。

如果需要某一模块（比如 JVM 调优、Spring 源码、Redis 高级特性）的更详细题目展开，可以告诉我，我再为你整理。祝你面试顺利！
