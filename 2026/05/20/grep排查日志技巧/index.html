grep排查日志技巧

发表于2026-05-20|更新于2026-05-20
|浏览量:

排查日志时，grep 是最核心的文本搜索工具。掌握它，能让你在成百上千兆的日志里快速定位问题。

1. 先看骨架：基本语法

2. 排查日志必学的 8 个选项

选项 作用 举例
-i 忽略大小写 grep -i "error" app.log 匹配 Error/ERROR/error
-n 显示行号，方便定位 grep -n "timeout" app.log
-v 反向匹配，排除干扰 grep -v "DEBUG" app.log 只看非调试行
-c 统计匹配行数，先看严重程度 grep -c "OutOfMemory" app.log
-A n 显示匹配行之后 n 行 grep -A 10 "Exception" app.log 看异常后10行堆栈
-B n 显示匹配行之前 n 行 grep -B 5 "ERROR" app.log 看错误前5行发生了什么
-C n 显示匹配行前后各 n 行 grep -C 3 "fail" app.log 获取完整上下文
-w 全词匹配，避免误判 grep -w "at" app.log 只找单词 at，忽略 cat/date

4. 进阶技巧

  • 大文件搜索性能
    如果只是找固定字符串（不含正则通配符），用 -F（或 fgrep）速度更快：
    grep -F "特定错误码" huge.log

  • 搜索时当作文本处理
    有些日志被识别为二进制，会提示 Binary file matches，加上 -a 强制当文本：
    grep -a "error" suspicious.log

  • 高亮匹配内容
    默认可能已带颜色，如果没有就加 --color=auto，阅读更直观。

5. 排查思路小结

  1. 先定性：用 -c 统计错误量，判断是突发还是持续。
  2. 再取样：用 -A/-B 截取一段典型错误，分析上下文。
  3. 定位时间：根据错误时间，用正则缩小日志范围。
  4. 排除噪音：用 -v 去掉 debug/info，聚焦关键信息。
  5. 关联分析：结合 sort | uniq -c | sort -nr 找出高频特征。

把这些命令组合起来，你手里的 grep 就是一个高效的日志分析引擎。
